# 阈值搜索与 ROC / PR 相关量如何计算

> 本文与 `lfw_eval` 中 `threshold.py`、`metrics.py` 的实现一致，便于对照代码与写报告。  
> 下文使用 **Unicode 与纯文本**，不依赖 LaTeX 渲染，在普通 Markdown 预览中即可阅读。

全局约定：**同人** label=1（正类），**异人** label=0（负类）；**相似度越大越像同人**；判定规则为 **`score >= threshold` 则判为同人**。

## 0. 记号与混淆矩阵（先统一口径）

以下定义都在“给定某个阈值 t、采用规则 `score >= t` 判同人”下成立：

- **P（Positive 总数）**：真实标签为 1 的样本数，即**同人对总数**。  
- **N（Negative 总数）**：真实标签为 0 的样本数，即**非同人对总数**。  
- **TP（True Positive）**：预测为同人，且真实也为同人。  
- **FP（False Positive）**：预测为同人，但真实是非同人。  
- **TN（True Negative）**：预测为非同人，且真实也为非同人。  
- **FN（False Negative）**：预测为非同人，但真实是同人。  

由此可得（注意“分子是计数，结果是比例”）：

- **Precision（精确率）** = TP / (TP + FP)  \n
  含义：被判为同人的样本里，有多少比例是真的同人。  
- **Recall（召回率 / TPR）** = TP / P = TP / (TP + FN)  \n
  含义：所有真实同人里，有多少被成功判为同人。  
- **FPR（假阳率）** = FP / N = FP / (FP + TN)  \n
  含义：所有真实非同人里，有多少被错误判为同人。  

补充关系：

- **P = TP + FN**，**N = FP + TN**。  
- 在本任务中，Recall 与 TPR 同义。

## 1. 计算测试集 Acc 时，「最佳阈值」在训练集上如何搜索？

**重要**：阈值**只在当前折的训练部分**（其余 9 折、且 `valid=True` 的样本）上搜索；**当前折的测试分数不参与选阈值**，因此测试 Acc 不会因「在测试集上调阈值」而虚高。

### 1.1 候选阈值怎么来（中点法）

1. 取出训练折上所有**有限**相似度分数，**去重**后得到升序序列：**u₁ < u₂ < … < uₘ**。
2. 在**相邻两个不同分数**之间取**中点**（**两者算术平均**）作为候选阈值。这样任意两个样本若分数不同，总有一个中点能把它们分到阈值两侧，避免「跳过」最优划分。
3. 在**最小分数左侧**、**最大分数右侧**各加一个略外推的边界候选（实现里为 **u₁ − ε**、**uₘ + ε**，其中 **ε** 为很小的正数，代码中取约 10⁻⁶），使得「几乎全判异人」或「几乎全判同人」这类极端情况也能被枚举到。
4. 若全体训练分数**只有一个取值**，则用该值及其左右微扰共三个候选，避免退化。

### 1.2 如何选「最佳」

对每个候选阈值 **t**：

- 在**同一份训练分数与标签**上，用 **`score >= t` 得到预测**，与真值比较，算 **训练准确率**。
- 取使训练准确率**最大**的 **t**；若多个 **t** 并列最优，取其中 **数值最小** 的 **t**（实现里用略大于浮点误差的比较），保证**可复现**。

### 1.3 测试 Acc

用上一步得到的 **唯一阈值 t**，在**当前折的测试子集**（仅 `valid` 位置）上再算一次准确率，即该折报告的 **test Acc**。  
因此：**阈值来自训练，Acc 在测试上算**，与 LFW 常见 10 折协议一致。

## 2. 和 Acc 不同：ROC / PR 里阈值是怎么「扫」的？

这是最容易和第 1 节混淆的地方，请先抓住一句话：

| | **Acc 最优阈值（第 1 节）** | **ROC / PR 曲线（本节）** |
|--|---------------------------|---------------------------|
| **目的** | 在训练折上**挑一个** t，使训练 Acc 最大 | 在**某个固定子集**（常是测试折）上，看 **t 连续变化** 时 TPR/FPR、Precision/Recall 怎么变 |
| **用到的数据** | 当前折的 **训练** 分数 | 你调用函数时传入的那份分数（多为**测试**折上各对的相似度） |
| **候选 t 怎么来** | **训练分数去重 → 相邻中点 + 两端**，有限个候选 | **不显式列中点表**；等价于：把所有有效样本按分数**从高到低排好**，再 **一次多放行一个「判同人」**，每步对应一类阈值区间（见下） |
| **拐点数量** | 只关心**一个**最优 t | 曲线上最多约 **样本数 + 1** 个（含首尾） |

### 2.1 具体扫法（ROC 与 PR 共用同一次排序）

在**当前要画曲线的那份子集**上（例如某一折测试里的所有 pair，且 `valid` 且分数有限）：

1. 记样本数为 **n**，同人总数 **P**，异人总数 **N**（PR 里主要用 **P**）。
2. 把所有样本按相似度 **从高到低** 排序（分数相同时用稳定排序 **mergesort** 打破并列，与实现一致）。
3. **扫描过程**：想象阈值 **t** 从 **+∞** 缓慢降到 **−∞**。  
   - 一开始没有任何人被判为同人；然后按排序顺序，**一个一个**把样本划入「判同人」。  
   - 每多划入 **1** 个样本，就产生 **ROC** 上的一个 **(FPR, TPR)** 中间点、**PR** 上的一个 **(Recall, Precision)** 中间点（PR 另有人工起点）。  
   - 因此：曲线上「有意义的」阈值步进与 **这 n 个样本各自的分数** 绑定；**不是在训练集上对「去重分数的中点」再枚举一遍**。

**与第 1 节的中点法的关系**：  
若只有两个样本、分数不同，中点法在训练上可以取两分数之间的中点为阈值；ROC/PR 在整条曲线上则必然经过「只放行最高分」「两个都放行」等状态，**等价于阈值落在排序造成的各个区间**。  
**Acc 的中点法**是为了在训练上**少量候选**里找**使 Acc 最大**的 t；**ROC/PR** 是为了**完整描述**「t 从严到松」全过程，所以用 **逐样本累计**，两者**算法不同、用途不同**。

### 2.2 `thresholds` 在 ROC 上代表什么？

实现里 ROC 返回的 `thresholds` 与 **(FPR, TPR)** 等长：依次为 **+∞**、排序后的 **每一个样本分数**（从高到低）、最后 **−∞**。  
每个中间拐点对应「已把前 k 个高分样本判为同人」时的累计 TPR/FPR；该点的 `thresholds` 项通常可取为**当前刚纳入的那条样本的分数**（与「**score ≥ 该值** 的预测集合在互异分数下与某一步累计一致」相对应；有并列分数时曲线会有平台段）。

PR 的 `PRCurve.thresholds` 是**去掉首尾人工点之后**的、排序后的分数数组，与 `precision` / `recall` 扩展数组的下标对齐方式见代码注释。

## 3. ROC 曲线（`roc_curve_masked`）如何得到？

（阈值扫法见 **第 2 节**。）

1. 若 P = 0 或 N = 0，无法定义 ROC，实现里返回退化折线。
2. 排序后，对「是否为同人」沿排序顺序做前缀累计：**TP**、**FP** 随放行人数增加而增加。
3. **TPR = TP / P**，**FPR = FP / N**；在累计序列前后补上 **(0, 0)** 与 **(1, 1)**，对应「全判异」「全判同」。

**画图**：横轴 **FPR**，纵轴 **TPR**。

---

## 4. PR 曲线（`precision_recall_curve_masked`）如何得到？

（同样依赖 **第 2 节** 的排序与逐步放行。）

1. 每放行一步：**Recall = TP / P**，**Precision = TP / (TP + FP)**。
2. 在最前补 **Recall = 0、Precision = 1** 的人工点（画图坐标 **(0, 1)**）。
3. **thresholds** 存排序后的分数，与扩展后的 `precision` / `recall` 下标对齐见实现。

**画图**：横轴 **Recall**，纵轴 **Precision**。

## 5. `auc_trapezoid`（ROC-AUC）如何计算？

- 用 ROC 点列：**x = FPR**（非递减），**y = TPR**。
- **梯形法则**：相邻两点连成梯形，面积 = **Δx × (y左 + y右) / 2**，再累加得到 **曲线下方面积**，即 **ROC-AUC** 的数值近似。

## 6. `average_precision_from_pr` 如何计算？和 ROC-AUC 的异同（是否都在算「平均」）

### 6.1 AP 怎么算

在 PR 离散点上：**AP ≈ 各相邻 Recall 区间上的 (Recall 增量 × 该段用的 Precision)，再全部相加。**  
（实现：对相邻 recall 差分，乘以后一点的 precision，再求和。）

### 6.2 和 ROC-AUC 的相同点

- **都不是**「把若干个阈值的标量取算术平均再除以个数」那种简单 **mean**。  
- 二者都是：在**阈值从严扫到松**（等价于第 2 节的逐步放行）之后，在一张平面上得到一条折线，再对标量轴做 **加权累积**：
  - AUC：**对 FPR 轴**积分 **TPR**（梯形）；
  - AP：**对 Recall 轴**积分 **Precision**（离散和近似）。

所以可以说：两者都是 **沿横轴的积分型汇总** → **一个数概括整条曲线**；但**横轴与被积函数不同**，数值**不可互推**。

### 6.3 和 ROC-AUC 的不同点

- **几何上**：一个在 **FPR–TPR** 平面算面积；一个在 **Recall–Precision** 平面算「Precision 相对 Recall 的积分」。  
- **语义上**：AUC 常与「正负可分成色」相关；AP 更贴「拉高召回时，判同人有多准」。  
- **类别不平衡**：负类很多时 ROC 有时仍较「好看」；正类少时 PR 上 Precision 波动大，**AP 往往更敏感**。

## 7. `max_tpr_at_fpr_cap` 与 `best_precision_at_min_recall`：各怎么算、有何异同

二者都是：**在已经算好的离散曲线**上，先 **按约束筛点**，再在可行点里 **做一个目标的 argmax**，并读出 **阈值**（用于部署或记录）。**不负责**重新扫阈值，只消费 `roc_curve_masked` / `precision_recall_curve_masked` 的输出。

### 7.1 `max_tpr_at_fpr_cap`（如 TAR@FAR）

- **输入**：`RocCurve`，内含逐点的 **FPR**、**TPR**、**thresholds**（与第 3 节一致）。另输入 **`max_fpr`**（允许的最大 FPR，即误把异人判成同人的比例上限）。
- **默认模式 `leq`**：在所有满足 **FPR ≤ max_fpr**（加微小浮点容差）的 ROC **离散点**里，取 **TPR 最大**的点；返回 **(该点 TPR, 该点实际 FPR, 该点 threshold)**。  
  - 直观：**误识率不超过给定上限时，真同人通过率能到多少、离散点上实际 FAR 是多少、阈值取多少**。
- **若无点满足 FPR ≤ max_fpr**：返回 **(nan, nan, nan)**。
- **模式 `closest`**：在 FPR 轴上找与 **max_fpr** **距离最近**的 ROC 点（实现细节见代码）；少用，一般业务用 **`leq`**。

### 7.2 `best_precision_at_min_recall`（Precision@Recall 约束）

- **输入**：`PRCurve`，内含 **Precision**、**Recall**、**thresholds**。另输入 **`min_recall`**（希望召回率不低于的下限）。
- **步骤**：在所有 **Recall ≥ min_recall** 的 **离散点**里，取 **Precision 最大**的点；返回 **(precision, recall, threshold)**。  
  - 直观：**至少找回这么多真同人时，判同人最准能到多少、阈值取多少**。
- **首点**常为人工 **(Precision=1, Recall=0)**，无有限阈值，若被选 **threshold** 为 **nan**。
- **若无点满足 Recall ≥ min_recall**：返回 **(nan, nan, nan)**。

### 7.3 相同点

- 都是 **约束优化**：可行域由 **一条轴上的不等式** 定义（ROC 上管 **FPR**，PR 上管 **Recall**）。  
- 都是 **离散曲线**：最优解落在**某个已实现曲线上**的顶点，不是连续解析解。  
- 都返回 **相似度阈值**（**最后一个**浮点数），与 **`score ≥ threshold` 判同人** 一致；`max_tpr_at_fpr_cap` 同时返回 **实际 FPR**，与 `best_precision_at_min_recall` 返回 **实际 Recall** 对称。

### 7.4 不同点

| 项目 | `max_tpr_at_fpr_cap` | `best_precision_at_min_recall` |
|------|----------------------|----------------------------------|
| **曲线** | ROC（FPR–TPR） | PR（Recall–Precision） |
| **约束** | **FPR 不超过** 上限（控误识） | **Recall 不低于** 下限（少漏真人） |
| **优化目标** | 在满足约束下 **TPR 尽量大**（多放真人进来） | 在满足约束下 **Precision 尽量大**（判同人更准） |
| **典型叙事** | 安防：**FAR 锁死**，看 **TAR** | 体验/报警质量：**找回率要有**，看 **精度** |

一句话：**前者**是「**坏事（误识）不能太多**，在此前提下好事（真通过）越多越好」；**后者**是「**好事（找回）要够**，在此前提下瞎报（低 Precision）尽量少」。

## 8. 与测试 Acc 所用阈值的关系（避免混淆）

- **测试 Acc 的阈值**：第 1 节，在 **9 折训练**上用 **中点候选 + 最大训练 Acc** 得到**一个** t，只用于该折测试 Acc。  
- **ROC / PR / AUC / AP**：第 2–6 节，在**指定子集**上 **逐样本排序扫** 得到**整条曲线**或积分标量；**不**保证该曲线上的某一点等于「训练 Acc 最优 t」。  
- **`max_tpr_at_fpr_cap` / `best_precision_at_min_recall`**：第 7 节，在已算好的 ROC / PR 上 **按业务约束选一个工作点** 及其阈值。

若并列汇报「Acc 最优阈值」与「TAR@FAR 工作点」，须**分别注明**阈值来源，避免混谈。

## 9. 常见追问（本轮补充）

### 9.1 ROC/PR 的点数是不是分别为 n+2、n+1？

设某次画曲线时（例如某折测试集）经过 `valid` 与有限值过滤后，剩下 **m** 个有效分数：

- **ROC**（当前实现）  
  - `thresholds = [+inf] + m个降序分数 + [-inf]`  
  - `fpr/tpr` 与 `thresholds` 等长  
  - 因此 ROC 点数是 **m + 2**

- **PR**（当前实现）  
  - 先按降序放行得到 m 个离散点  
  - 再补一个人工起点 `(Recall=0, Precision=1)`  
  - 因此 `precision/recall` 点数是 **m + 1**，而 `thresholds` 长度是 **m**

你的说法「n+2（ROC）和 n+1（PR）」是对的，只要 n 指的是该次曲线计算用到的**有效分数个数**。

补充：分数有并列时，曲线可能出现平台/重合段，这是离散曲线的正常现象，不影响上述长度关系。

### 9.2 为什么 AP 常写成 `ΔRecall × Precision右端`，而 ROC-AUC 用梯形？

先说结论：两者都在做“积分型汇总”，但**被积函数、离散近似习惯和语义**不同。

- **ROC-AUC（梯形）**  
  - 在 ROC 平面上对 `TPR(FPR)` 积分  
  - 采用线性连接相邻点的假设，故用梯形：`ΔFPR × (TPR左 + TPR右) / 2`

- **AP（当前实现）**  
  - 在 PR 平面上对 `Precision(Recall)` 做离散积分  
  - 实现为“右端和”：`ΔRecall × Precision右端` 再求和

为什么 AP 用右端更常见？直觉是：当阈值下降、Recall 增加到“新区间右端”时，这一段新增召回对应的是“当前工作点”的 precision；因此用右端 precision 给这段 recall 增量计权，和检索/排序评估中的 AP 离散定义一致。

所以它们的联系与区别是：

- **联系**：都不是简单算术平均，都是“沿横轴加权累积”得到单个摘要值；
- **区别**：AUC 在 FPR 轴上积 TPR（更偏区分能力），AP 在 Recall 轴上积 Precision（更偏召回推进时的精度质量）；
- **计算方式不同并非偶然**：对应的是两种曲线在评估语义上的不同传统与定义。
